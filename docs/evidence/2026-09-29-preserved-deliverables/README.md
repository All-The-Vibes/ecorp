# Preserve complete deliverables across governed recovery

Issue #89. A narrowed contract or finish scope must not discard source already retained in a stopped provider worktree. The implementation records complete physical and staged source identity after provider termination, binds it to the run, workspace, mission, room and Corp, and rejects incompatible revisions. Before the same native provider session resumes, the runner rechecks the checkpoint, index, artifact exclusions and native export selection. It does not silently widen authority or compose an unverified parent artifact.

## Review and limits

The existing typed export failure and prohibition on fresh-worktree retry came from PR #355. This change fills the missing narrowing and pre-provider guards; new retrospective evidence is not September 3 production evidence. Provider artifacts are excluded only when authenticated and byte-identical to a normal stage-0 file; staged deletion, conflicts, non-file modes, differing bytes and raw line-ending changes cannot be hidden. The runner reuses native resume, existing exporter, checkpoint locks and durable runner commands through the pinned harness adapters.

See `REVIEW.md`, `summary.json` and `source-equivalence.json` for source references, checks and limitations. In particular, the full-ECorp r6 target exceeded its checkpoint deadline; this small scenario does not establish large-workspace performance. Controlled authentication/provider fixtures do not prove production OIDC or live inference. Historical Cargo advisory debt is not a clean audit. Local readiness does not replace required hosted CI, CodeQL, security or eligible review. Issue #89 is not completed until the linked implementation PR is merged and its final state is verified.
