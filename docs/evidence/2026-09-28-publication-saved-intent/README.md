# Retire invalid saved publication intent

PR #380 could leave a malformed saved human request eligible on every watcher poll. Decoding errors, a missing original request operation, or an actor/plan mismatch escaped its durable rejection path. This correction classifies pure proof errors with the existing typed denial and validates the saved request after authenticated native locking. It adds no migration or execution mechanism.

The worker authenticates the enrolled credential and repository, observes the publication without a row lock, acquires its four existing native gates, then rereads and validates the exact row. Changed gate identity aborts. Tagged invalid human intent is retired only without a live lease. The original request key cannot be reused. An existing watcher key must bind the same publication, actor, publisher and lease request. Invalid proof creates no start operation, publisher token, lease or new attempt. Failure replay is tokenless and creates no second event. Database errors remain retryable; failure or event write errors roll back. Valid requests continue through native start and its prerequisite rechecks.
